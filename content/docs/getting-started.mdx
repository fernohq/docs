## Browser

```bash
npm install @fernohq/analytics-next
```

```ts
import { AnalyticsBrowser } from '@fernohq/analytics-next'

const writeKey = import.meta.env.VITE_FERNO_WRITE_KEY

export const analytics = AnalyticsBrowser.load({
  writeKey,
  cdnSettings: {
    integrations: {
      'Segment.io': {
        apiKey: writeKey,
        apiHost: 'data.useferno.com',
        apiPath: '/events',
        authMode: 'bearer',
        retryQueue: true,
      },
    },
  },
})
```

For Vite, `import.meta.env.VITE_FERNO_WRITE_KEY` reads the browser/project write key. The explicit `cdnSettings` ensures events use Ferno's `/events` endpoint without remote settings discovery.

Before adding broader instrumentation, send one first event and verify it in the browser Network panel:

```ts
analytics.track('Opened pricing page', { source: 'navigation' })
```

Confirm the POST request reaches `/events` and returns a successful HTTP response. Surface rejected SDK promises during development; console logs alone do not prove delivery. Do not put a secret server credential in browser code.

## Node

```bash
npm install @fernohq/analytics-node
```

```ts
import { Analytics } from '@fernohq/analytics-node'

const analytics = new Analytics({ writeKey: process.env.FERNO_WRITE_KEY! })
analytics.track({
  userId: 'user-123',
  event: 'Completed checkout payment',
  properties: { plan: 'pro', currency: 'USD' },
})
await analytics.closeAndFlush()
```

Keep Node keys in environment variables or a secrets manager.

## First instrumentation checklist

1. Write the business question the events should answer.
2. Define an event dictionary with stable names and descriptions.
3. Track behavior and outcomes, not form values or free text.
4. Add `identify` after authentication.
5. Add server-confirmed events for payment and subscription outcomes.
6. Review payloads for confidential information before production.

```bash
pnpm build
```

Deploy the generated `dist/client` directory to your static host.
